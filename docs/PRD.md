# 求职面试 Agent 产品需求文档（PRD）

版本：0.2　日期：2026-09-30　状态：对话式改造基线

## 1. 产品定位

面向中国求职者、支持任意岗位的对话式求职 Agent。聊天是唯一主界面：用户用自然语言提问、上传或粘贴 JD 和简历，系统在每条消息到达时调用 LLM 判断意图，再动态启用合适的 Skill。提问、追问、分析与报告都出现在同一段对话中；侧栏只用于切换会话，设置用于管理模型、偏好和自定义 Skill。

内置 Skill 包括普通求职会话、面试深挖、JD 与简历匹配、公司背调。没有岗位专属 Skill 时，依据真实 JD 生成通用面试计划。生成文本不得覆盖原始资料，事实性结论应能回指上传材料、用户回答或公开来源。

## 2. 目标用户与体验

| 场景 | 用户在聊天中说什么 | Agent 应做什么 |
| --- | --- | --- |
| 普通求职咨询 | “这个岗位值得投吗？” | 使用求职会话 Skill 回答，并说明所依据的资料与不确定性 |
| 上传或粘贴材料 | 上传 JD、简历，或粘贴岗位描述 | 解析、预览并关联到当前会话；缺文字时提示修正 |
| 模拟面试 | “按这份 JD 面我 20 分钟，难一点” | 启用面试 Skill，一次一问，按回答追问，到时或主动结束后在对话中复盘 |
| 岗位匹配与简历 | “对照 JD 改我的简历” | 启用匹配 Skill，列证据和缺口，返回可审核的简历草稿 |
| 公司背调 | “帮我查一下这家公司” | 使用受控 MCP 搜索，列可打开的来源与访问时间；未查到时明确说明 |
| 更换模型 | 在会话中选择另一可用模型 | 从下一次调用起使用新模型，保留当前材料、Skill 阶段和历史 |
| 定制 Skill | 在设置中创建或修改 Skill | 保存配置型阶段、提示词和评分规则，后续对话可动态选用 |

## 3. 核心交互

1. 用户进入现有聊天页，可直接发问，也可在输入区上传或粘贴材料。材料预览显示文件名、类型、解析状态与原文；扫描 PDF 没有文字时要求用户换文件或粘贴文本。
2. 每条用户消息都经过 LLM 意图识别。路由器结合当前消息、近期对话、已关联材料、进行中的 Skill 和用户显式选择，返回意图、可选 Skill 与提取参数；服务端再判断任务动作和缺失输入。无法确认用户是否把一段话作为面试答案时先追问；路由失败须提示重试，不擅自执行别的任务。
3. 运行器只加载本轮选中的 Skill 配置，按其阶段调用模型与批准的工具。进行中的面试可接收回答、继续追问或结束；用户可在同一聊天中切换任务。
4. Skill 输出成为对话消息或结果卡片，可在原位置展开来源、复制内容、继续追问或要求修改。没有单独的“工作台”或“历史结果”页面。
5. 会话侧栏展示聊天历史。刷新后恢复已保存的面试与分析结果；公开版进一步把完整对话及材料关联迁到服务端。

“定向简历草稿”源于用户最初要求按 JD 生成一份新简历。目标是在聊天中返回可继续修改的文稿，标明原始经历依据和待确认项；用户审核前不把它当作真实简历。独立“历史结果”列表撤下，完成结果留在会话消息中；内部运行记录仍可用于恢复与审计。

模型切换不重跑已经生成的内容。每次运行记录本轮 `modelId`、Skill ID/版本和引用资料；路由模型可由服务端单独指定，不随用户切换的生成模型改变。

## 4. 功能需求与验收

### P0：本地对话闭环

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P0-01 | 每条消息 LLM 意图识别 | 普通咨询、面试、匹配、背调分别进入对应 Skill；不能只依赖关键词；结构化路由失败有可见错误 |
| P0-02 | 动态 Skill | 内置求职会话及三个专项 Skill 可由路由选中；自定义 Skill 在设置中创建、编辑、删除，且不执行用户脚本 |
| P0-03 | 聊天中上传/粘贴材料 | PDF、DOCX、TXT、MD 可抽取文本；粘贴文本可作为 `.txt` 材料上传；文档有独立 ID，错误格式、超限、扫描 PDF 有明确提示 |
| P0-04 | 同一会话完成任务 | 面试追问、匹配报告、公司来源在消息流中展示；用户可对结果继续提问，不跳转独立页面 |
| P0-05 | 模型中途切换 | 至少两个服务端模型配置可选；切换后下一轮生效，不丢失会话材料与进行中的面试 |
| P0-06 | 风格延续 | 沿用现有侧栏、消息气泡和输入区的视觉语言，桌面与窄屏均可操作 |
| P0-07 | 来源与事实边界 | 简历改写不虚构经历；背调无有效来源时不调用模型编造公司事实；报告展示材料或网页来源 |

### P1：公开 Web 版门槛

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| P1-01 | 登录与数据隔离 | 未登录不能访问私有会话、资料、Skill；双账号测试无法越权读取、修改或删除 |
| P1-02 | 服务端会话持久化 | 聊天消息、附件、Skill 状态及结果在刷新、设备切换、服务重启后恢复；所有读取按会话所有者校验 |
| P1-03 | 用户偏好与记忆 | 用户可设置目标岗位、语言、难度、面试时长及反馈方式；长期事实只在确认后保存，并可查看或删除 |
| P1-04 | 成本与滥用控制 | 用户/IP 额度、并发、上传限制和模型/MCP 超时生效；敏感正文和密钥不进默认日志 |
| P1-05 | 数据权利 | 会话、材料、自定义 Skill、记忆可删除；有备份、保留和恢复策略 |
| P1-06 | 解析与成果质量 | 扫描 PDF/图片 OCR、更多常见文档格式、修改对照、事实核验、DOCX/PDF 简历导出经真实中文样本验证 |
| P1-07 | 真实 MCP 搜索验收 | 公司主体消歧，官网/新闻/评价区分，URL 与访问时间可见；搜索失败或无结果不产生确定性事实 |

### P2：多端与质量增强

- 微信小程序作为第二个客户端，复用 Web 使用的 Express API、会话、Skill 和模型运行器；小程序只实现自己的界面与登录接入。
- 语音面试、错题复练、跨场次弱项趋势，以及用户授权的跨会话记忆。
- 从 GitHub `SKILL.md` 转换为待审核草稿；检查许可、依赖和工具权限后才允许启用。
- 按真实需求扩展独立协议模型、用户自带密钥与更多批准的 MCP 工具。

## 5. Skill 与意图路由约定

路由输出包含 `intent`、可选 `skillId` 和从消息提取的任务参数；服务端根据会话状态校验 Skill 类型、决定下一步并逐项询问缺失材料。普通求职会话是默认 Skill；专项 Skill 可处理“开始、继续、修改、结束”等动作。会话中存在进行中的面试时，用户回答仍经过意图识别，以便识别“结束面试”或“先聊别的”。用户在设置中创建的 Skill 只有配置数据，没有可执行脚本或环境变量权限。

Skill 包含 ID、版本、名称、适用意图、阶段、提示词、输出约束与平台允许的工具。单轮只激活一个主 Skill；其他 Skill 的结果通过结构化数据引用，不把所有提示词拼进一次请求。自定义 Skill 可调整阶段和评分，但无法指定 MCP URL、令牌或扩大工具白名单。

| 内置 Skill | 输入 | 核心规则与输出 |
| --- | --- | --- |
| 求职会话 | 当前消息、相关资料、偏好 | 处理普通求职问题与澄清；不把推断写成已确认事实 |
| 面试深挖 | JD、简历、时长、难度 | 依据任意岗位 JD 定计划，一次一问，按证据追问；服务端限制轮数和时间，结束后复盘 |
| JD 与简历匹配 | JD、原始简历 | 拆解要求、对应证据、区分表达缺口与真实缺口；给待审核定向简历和短期可补知识点 |
| 公司背调 | 公司名称、可选 JD | 先搜索公开资料，再区分官网事实、新闻与评价；每条发现引用来源，无来源返回“未查到” |

## 6. 上下文、模型与工具

- 对话上下文按本轮任务组装：平台规则、选中的 Skill 阶段、当前消息、关联 JD/简历片段、已确认偏好、会话摘要与最近几轮。完整记录留在存储中，不无限追加到每次模型请求。
- 原件、解析文本、用户确认事实、模型推断、生成稿分别保存。用户材料和网页都视作不可信内容，不能覆盖系统规则。
- 模型网关统一流式文本和结构化输出；路由模型可通过 `AI_ROUTER_MODEL_ID` 固定，否则使用本轮选中的模型或默认模型。模型能力不足时显示错误，不假装支持工具调用。
- MCP 由服务端配置固定搜索地址、令牌、工具名和参数名。用户消息、自定义 Skill 和上传资料都不能控制连接目标。搜索结果附 URL 与访问时间；无有效 URL 时不生成公司事实。

## 7. 本地版与公开发布边界

当前本地版使用固定 `ownerId=local`，部分普通聊天历史仍由浏览器保存。面试和分析记录已有服务端本地持久化，但这不等于多用户隔离；不得以当前形态公开部署。Node 24 `node:sqlite` 可用于本地单实例，公开版须补认证、所有数据访问的 owner 校验、持久存储/备份、删除和额度。

未来 Web 与微信小程序共用一个后端：客户端只负责输入、消息流、预览和设置；意图识别、Skill 运行、资料访问、模型密钥与 MCP 凭据都留在服务端。公开版优先实现服务端会话 API，再接入小程序，避免在两个客户端复制 Agent 逻辑。

## 8. 成功标准

1. 技术岗与非技术岗用户都能在同一聊天页上传 JD 并自然发起匹配、面试和背调；路由选择符合用户当前意图。
2. 面试时可切换模型并继续，追问引用当前 JD、简历和用户回答；报告回指具体证据。
3. 用户自定义 Skill 能改变流程；不能通过 Skill 或文档调用未授权 MCP 工具。
4. 公司背调所有事实性发现有可打开的网址和访问时间；搜索无结果时没有生成事实。
5. Web 公开版通过双账号隔离与会话恢复验收；小程序上线前再用 Web 和小程序分别验证同一账户的会话恢复。
